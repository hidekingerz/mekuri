# RULES — エージェントが絶対にやってはいけないこと

> VERIFY の品質ゲートと並ぶガードレール。PLAN / EXECUTE でこのルールを最優先で守り、抵触する場合は変更しない。

## 禁止事項（Hard rules）

- `main` ブランチへ直接コミット・push しない。作業は必ず `feat/deno-desktop-migration` ブランチで行う（現在このブランチにいるはず。違ったら何も変更せず Open に記録して終了）。
- `src-tauri/` 配下を変更・削除しない（参照・ロールバック用に残す）。
- `src/components/` など React 本体の機能を変更しない。変更してよいのは `src/api/` の配線替えのみ（マイルストーン3）。
- VERIFY（`cd deno-app && deno task verify`）が通っていない変更をコミットしない。
- 既存テストを「通すために」削除・スキップ・無効化しない。
- canary deno をユーザーの stable 環境へ勝手にインストール・`deno upgrade` しない。マイルストーン4・6 で canary が必要なのに無い場合は、着手せず Open に記録する。
- 1周で多数ファイルにまたがる大規模リファクタをしない（1周 = 1タスク、最小変更）。
- 秘密情報・認証情報をコード・ログ・コミットに書かない。
- `loop/` 配下（このループの設定）と `docs/superpowers/specs/` を勝手に書き換えない（`loop/MEMORY.md` への追記は除く。MEMORY は毎周更新する）。

## 進め方の原則

- このプロンプトは自律実行ループである。`brainstorming` / `writing-plans` 等のメタ/プロセス系スキルは起動せず、`LOOP_PROMPT.md` の5段階を直接実行する。このプロンプトとリポジトリ内ドキュメントが唯一の指示源。
- 判断に迷ったら**安全側（変更しない）**に倒し、`loop/MEMORY.md` の Open に判断ポイントを記録する。
- VISION.md のマイルストーンは上から順に進める。着手中のものがブロックされたら、着手可能な次のものへ。
- ライブラリ選定（RAR 展開・PDF 等）は PLAN 段で調査し、`deno.json` の `imports` に追加する（依存追加はこの移行作業の一部として許可。ただし追加理由を MEMORY に記録）。
